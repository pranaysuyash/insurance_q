# CoverWise Onboarding Rebuild — 2026-07-13

## Analysis

### Current state
- 3-page static info carousel, no data capture, no account creation
- Anonymous device-level JWT only — no accounts, no email, no phone, no durability across devices
- Lead capture dialog (email/phone) fires on EVERY upload, is optional, and data never leaves the device
- No analytics — can't measure funnel, retention, or user identity across sessions
- The user asked: "users can create accounts? I can run analysis on them?" — answer to both is currently NO

### First-principles decision: phone-number as progressive identity

**No account wall.** The user reaches first value (seeing their policy summary) WITHOUT entering any identity. This maximizes conversion at the most vulnerable moment.

**Phone capture AFTER first value.** Once the user has uploaded a policy and seen their summary, prompt: "Your policy is saved on this device. Add your number to access it from any device." This is a value exchange, not a gate.

**Why phone, not email:** Indian users are phone-first. OTP is instant. Phone is the natural recovery key. It provides durable identity for analytics without password friction.

**Why progressive, not blocking:** every identity field before first value is friction that kills conversion. The user should experience value before being asked to commit identity.

**No SMS OTP for solo launch (costs money).** Phone is stored locally + linked to anonymous UID. When SMS provider is added later, upgrade path is clean. The "account" is phone-linked-UID.

## What to build

### 1. Rich onboarding carousel (replace current `onboarding_screen.dart`)
- 3 slides with visual mockups (not just text+icon):
  - Slide 1: "Understand Your Insurance" — shows a before/after visual (dense policy text → clean summary card with benefits/exclusions)
  - Slide 2: "Ask Anything" — shows a chat-style Q&A mockup with a real question and sourced answer
  - Slide 3: "Private by Design" — lock icon, offline badge, "delete anytime" 
- Smooth animated transitions, gradient backgrounds matching brand (#1565c0 blue)
- Animated progress dots
- "Get Started" CTA on final slide, "Skip" on all slides
- Emits analytics events: `onboarding_started`, `onboarding_slide_viewed`, `onboarding_completed`

### 2. Improved empty-state dashboard
- Replace bare "0 documents" with a prominent, visual first-upload CTA card
- "Upload your first policy" with illustration, "Takes 30 seconds. Works offline."
- Makes the next action obvious and inviting

### 3. Progressive phone capture (post-value bottom sheet)
- New widget: `PhoneCaptureSheet` — triggered after first successful upload
- Message: "Your policy is saved on this device. Add your number to access it from any device and never lose it."
- Phone input (Indian format +91), [Add Number] / [Maybe Later]
- Smart re-prompt: ask after 1st upload, then after 2nd upload, then never again
- Stores phone in Hive linked to anonymous UID
- Emits: `phone_capture_shown`, `phone_capture_completed`, `phone_capture_dismissed`

### 4. Local analytics service
- New: `mobile/lib/services/analytics_service.dart`
- Stores events in Hive (offline-first), batch-syncs to backend `/analytics/events` when online
- Events from the existing spec (`docs/review/coverwise_analytics_event_spec.md`):
  - Onboarding: `onboarding_started`, `onboarding_slide_viewed`, `onboarding_completed`
  - Core funnel: `first_upload_started`, `first_value_delivered`, `question_submitted`, `answer_rendered`
  - Identity: `phone_capture_shown`, `phone_capture_completed`, `phone_capture_dismissed`
  - Engagement: `answer_feedback_submitted`, `support_intent`
- All events carry the anonymous UID for cross-session identity
- No PII in event payloads (per the spec)

### 5. Backend analytics endpoint
- `POST /analytics/events` — accepts a batch of events from the mobile app
- Stores in SQLite (the existing `insurance_app.db`) for solo-launch simplicity
- No PII stored — only event name, timestamp, anonymous UID, and safe properties

### 6. Settings: show identity + add/change phone
- Settings screen shows: "Device linked" or "Linked: +91••••••1234"
- Option to add/change/remove phone number

## What this does NOT do (deliberate scope)
- No SMS OTP (costs money, needs provider — phone is stored locally for now)
- No cross-device sync (requires backend document storage, being built by parallel agent)
- No social login (Google/Apple — can add later)
- No KYC/Aadhaar (this is a document reader, not financial service)
