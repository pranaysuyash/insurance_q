# Implementation Plan: CoverWise Full Product Build-Out

## Goal
Close the gap between the product spec (`docs/planning/product/coverwise_product_spec_2026-07-12.md`) and what exists, in priority order. Every change is first-principles, long-term, motto_v3-aligned.

## Phase 1: Fix the data layer (bugs that break everything downstream)

### 1A. Fix date field mismatch (backend → mobile)
**File:** `mobile/lib/models/policy_summary.dart` — `fromJson`
- Backend emits `effective_date`/`expiration_date`; mobile reads `start_date`/`end_date`.
- Fix: add aliases in `fromJson` so it reads both: `json['start_date'] ?? json['effective_date']` and `json['end_date'] ?? json['expiration_date']`.
- Also update `toJson` to emit both key sets (backward compat with any stored data).

### 1B. Unify type classification
**New file:** `mobile/lib/utils/policy_type.dart`
- A single canonical `PolicyType` enum: `health, auto, life, home, travel, other`.
- A `classifyPolicyType(String documentType)` function that handles Indian terms: "mediclaim" → health, "family floater" → health, "two wheeler" → auto, "term plan" → life, "ulip" → life, "endowment" → life, "critical illness" → health, etc.
- A `canonicalTypeName(PolicyType)` returning "Health Insurance" etc. for display.
- Update `document_icons.dart` to use the enum.
- Update `policy_extraction_service.dart` `analyzeCoverageGaps` to use the enum.
- Update `dashboard_screen.dart` type counts to use the enum.
- This eliminates the fragile `.contains('health')` matching in 4+ places.

### 1C. Fix delete cascade (provider invalidation)
**File:** `mobile/lib/screens/documents_list.dart`
- After delete: invalidate `documentsListProvider`, `documentsProvider` (dashboard), `documentsForQaProvider` (QA), call `policySummariesProvider.notifier.deleteSummary(docId)`, invalidate `mergedFamilyMembersProvider`, clear stale `selectedDocumentId` if it matches.
- Need to expose the dashboard/QA providers publicly or move them to `document_providers.dart`. Move them there (single source of truth — motto §7).

### 1D. Fix "Clear local data" to actually clear Hive
**File:** `mobile/lib/screens/settings_screen.dart`
- Clear `documents_box`, `app_state_box`, SharedPreferences, and physical document files.
- Invalidate all providers after clearing.

## Phase 2: Build the policy detail screen (the missing core value)

### 2A. New screen: `policy_detail_screen.dart`
**Route:** `/policy-detail` (pushNamed with documentId argument)
- Receives a `documentId`, finds the matching `PolicySummary`.
- Displays ALL extracted data in organized sections:
  - Header: type icon, type name, insurer, status badge, policy number
  - Money row: coverage amount, premium + frequency, deductible
  - Dates: effective → expiration, days remaining
  - "What's Covered" section: `keyBenefits` as a checklist
  - "What's Not Covered" section: `exclusions` as a list with ✕ icons
  - "Waiting Periods" section: `waitingPeriods` as info cards
  - "Coverage Items" section: `coverageItems` as a table (name, limit, covered ✓/✕)
  - Quick actions: Ask a Question (→ QA with this doc), Claim Guide (→ claims with this doc), Call Insurer, Email Insurer
- Graceful empty states for each section ("No exclusions found in this policy")
- "Extraction incomplete" banner if key fields are null

### 2B. Make dashboard policy cards tappable → policy detail
**File:** `mobile/lib/screens/dashboard_screen.dart`
- Wrap `_PolicyCard` in `InkWell`/`GestureDetector` → `Navigator.pushNamed('/qa', ...)` → change to `/policy-detail`.

### 2C. Make document list items tappable → policy detail
**File:** `mobile/lib/screens/documents_list.dart`
- "Ask Questions" stays, add tap on card → policy detail screen.

- Claim tracking with status/filed-date (requires persistent storage migration first)
